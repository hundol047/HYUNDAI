# 0.10.4 실행 녹화와 화면 점검

두 영상 모두 **실제 Chromium에서 앱을 실행하며 연속 녹화한 화면**입니다. 사진을 이어 붙인 영상이나 실차·Android 실기기 녹화가 아닙니다. 화면에 사용하는 데이터 종류를 표시했습니다. MP4는 H.264, 1440×1050, 무음이며 [길이·체크섬](validation/video-v0104.json)을 함께 기록했습니다.

- [리스본 가게 검색 → 경로 안내 → 도착](video/CabinOS_ONE_world_shop_v0104.mp4), **148.60초**: 실제 Nominatim 검색 결과 `A Brasileira`를 선택하고 실제 OSRM 경로·OSM 지도 타일로 주행합니다. 위치는 실제 경과 시간에 맞춰 매초 입력한 합성 GPS입니다. 검색·도로·회전·가게 주소·도착·정차 후 지도 확대를 확인했습니다.
- [GPS 모호성·복구와 차량 접근 지점 안내](video/CabinOS_ONE_gps_access_v0104.mp4), **42.32초**: 이스탄불과 퀸스타운의 기록된 실제 OSRM 경로를 재생하고, 화면에 보이는 지도 타일은 실제 서버에서 읽습니다. 위치·시간은 검사용 합성이며 중간 지점으로 가속 재생합니다. 영상 길이를 주행 시간이나 5시간 검사 시간으로 환산하지 않습니다.

## 확인한 동작

| 장면 | 확인 결과 | 화면 |
|---|---|---|
| 이스탄불, 위치 오차 25m·방향 정보 없음 | 서로 반대 방향의 도로가 정확도 범위에 들어오면 회전 화살표·거리·음성 안내를 보류하고, 남은 거리는 대략적인 값으로 표시 | [GPS 모호성](validation/navigation-confidence-v0104/uncertain.png) |
| 같은 위치, 정확도 5m·진행 방향 복구 | 회전 안내를 재개하며 실제 GPS 표시도 5m로 바뀜 | [복구](validation/navigation-confidence-v0104/recovered.png) |
| 퀸스타운, 차량 경로 끝과 목적지가 약 51m 떨어짐 | `Vehicle route endpoint · Destination: ≈ 51 m`로 차량 접근 지점과 목적지를 구분. 31개 지원 안내 언어의 접근 지점 문구를 단위 검사 | [차량 접근 지점](validation/navigation-confidence-v0104/vehicle-access.png) |

[녹화 실행 결과](validation/navigation-confidence-v0104/results.json)에 실제 엔진 해시와 두 장면의 상태를 보관했습니다. 음성이 없는 환경에서 음성 출력을 했다고 표시하지 않으며, GPS 모호 시 음성 보류·복구 동작은 별도로 브라우저 Speech API와 Android TTS API 모의 검사에서 확인했습니다. 이 검사는 마이크 실발화나 음향 품질 검사가 아닙니다.

주행·검색 화면에서 도로와 상호의 표시를 확인했지만, 타일에 모든 가게가 등록돼 있음을 뜻하지 않습니다. 강원 위치에서 `대관령 옛길`을 검색하면 서울의 동명 식당이 반환되는 실제 사례도 확인했습니다. [146.7km 거리·업종·주소 경고](validation/namesake-v0104/search.png)를 표시하며, 이 결과를 강원의 도로로 바꾸거나 자동으로 목적지로 선택하지 않습니다.

5시간 검사 전체 범위와 수정 내역은 [글로벌 모의 주행 보고서](WORLD_SOAK_KO.md)를 참고하세요.

# GPS·기능 실행 재점검 · 0.9.0

실행한 검사와 외부 서버 응답을 기준으로 판단했습니다. 이 환경에는 물리 GPS와 안정적으로 실행되는 Android 장치가 없어 **실기기 위성 수신·실차 주행·Pleos 호환성은 검증하지 못했습니다.** 테스트 좌표를 실제 GPS 수신 성공으로 표현하지 않습니다.

## 발견하고 수정한 GPS 문제

| 문제 | 수정과 재현 근거 |
|---|---|
| Android가 최소 1m 이동해야 위치를 갱신하도록 요청 | 최소 이동 거리를 0m로 변경하고 1초 간격 요청 유지. 실제 LocationManager 테스트 제공자로 같은 좌표를 12초 넘게 보내도 위치가 최신이며 시작 가능한지 검사 |
| 기존 수신기가 등록되어 있으면 다시 연결 버튼이 무효 | 명시적 재연결은 이전 등록을 제거하고 새 수신기 등록. 구독 번호로 종료된 수신기의 늦은 콜백도 차단 |
| 처음부터 GPS가 오지 않거나 위치가 오래되어도 정상/대기 표시가 남음 | 첫 응답 15초 대기와 최신 위치 10초 만료를 구분. 미연결·수신 대기·정상·부정확·오래됨·권한 거부·위치 중지 상태 표시 |
| 권한을 해제한 뒤 기존 좋은 위치가 남음 | 권한을 다시 확인해 기존 위치·시작 가능 상태를 무효화하고 수신 등록 해제. 정차 중 실제 Android 위치/앱 권한 설정 Intent 제공 |
| 정확한 GPS 사이에 부정확한 기지국/Wi-Fi 위치가 들어와 안내 중단 가능 | 3초 이내의 정확한 GPS보다 나쁜 네트워크 위치는 채택하지 않음. GPS 자체의 정확도가 나빠지면 기존처럼 즉시 시작 제한 |
| 브라우저의 일시적 오류에서도 수신기를 완전히 제거 | 일시적 수신 실패/시간 초과는 안내를 중지하되 구독 유지. 새 유효 위치가 오면 자동 복구. 권한 거부는 정리 후 명시적으로 재연결 |
| 브라우저가 위치 API 호출 자체에서 예외를 던지면 화면 오류 | SecurityError 처리, 동기 권한 거부 후 반환되는 수신 ID도 정리, HTTPS/권한/기기 위치 설정 안내 |
| 신호가 끊기거나 화면 밖에 있던 시간이 정지 확인에 포함 | Android/웹이 같은 연속 정지 판정 사용. 유효 위치가 5초간 연속 들어와야 하며 2.5초 초과 간격·부정확 위치·미확인 속도·좌표 이동은 누적 초기화. 이후 차량 P 상태도 별도 재확인 |
| GPS 상태 갱신이 어시스턴트 음성을 반복해서 중단할 수 있음 | GPS 미사용/이미 오래됨으로 처리한 상태에서 어시스턴트 음성을 매초 취소하지 않도록 개선. 브라우저는 내비 음성 소유·재생 세대를 구분해 늦은 완료 콜백도 차단. TTS/디스패처 회귀 검사 |
| GPS 복구 뒤 같은 회전 문구가 음성으로 다시 요청되지 않음 | 중단 시 음성 중복 억제 상태 초기화. 복구 후 현재 안내 재요청을 Android TTS API와 브라우저 음성 디스패처로 확인 |
| 주행 중 재연결이 새로운 브라우저 위치 권한 창을 열 가능성 | 주행/안전 잠금 상태에서는 이미 허용된 권한인지 확인. 허용을 확인할 수 없으면 새 위치 요청 없이 주차 후 설정 안내. Android도 주행 중 새 권한/설정 화면을 열지 않음 |

위치 데이터는 메모리에서 처리하며 Room/설정에 저장하지 않습니다. 앱이나 브라우저 탭이 백그라운드로 가면 위치·안내를 중단합니다. 개인 데이터 초기화는 이전 콜백과 자동 재연결 의도도 제거합니다. GPS가 있다고 차량의 P 상태를 인정하지 않습니다.

## 실행 근거와 기능 판정

| 기능 | 이번 확인 | 판정 범위/남은 부분 |
|---|---|---|
| GPS 연결·재연결·권한·시간 초과·오래됨·정차 갱신 | Android 프레임워크 등록/콜백·권한·설정 Intent, 실제 Chromium 위치 API 흐름 **15개** | 제공자/좌표/권한 결과는 명시적 검사 입력. 물리 위성 수신 아님 |
| GPS 복구 후 음성 안내 | Android TextToSpeech API 기록과 브라우저 디스패처 재요청 | 한국어 언어팩·실제 소리·음성 인식 품질은 장치에서 확인 필요 |
| 실제 지도·주소 검색·자동차 경로 | OSM 타일, 서울역 주소, OSRM 4.01km 경로 요청 3개 HTTP 200. 실제 Chromium 검색·도로 표시·안내 시작도 성공 | 브라우저의 출발 GPS만 공개 장소의 합성 좌표. 실시간 교통·차선/실도로 정확도 인증 아님 |
| 상호·지점·주소 검색·더 보기 | 기존 가게 검사 12개, 저장된 실제 국제 가게/경로 응답 회귀 유지 | 모든 상호/도로의 등록·연결을 보장하지 않음. 카카오 실서버는 키 미등록 |
| 주변 장소 추천의 외부 제공자 | 같은 판교 공개 좌표의 작은 Overpass 요청을 다시 실행했으나 **HTTP 502** | **실서버 정상으로 판정하지 않음.** 외부 서버 장애를 저장소 코드로 복구할 수 없었음. 앱의 오류/재시도·예시 표시 구분은 검사 통과. EchoRoad의 상호 검색은 별도 제공자 사용 |
| 주행·신호 대기·주차·충전 전환 | 공통 엔진 및 Android/브라우저 전환·조작 제한 검사 | 차량·충전 신호는 시뮬레이션, Pleos 실차 미연동 |
| 집중·휴식·할 일·공유 출발 시간·이력 | 기존 코어·Compose·Room·브라우저 실행 검사 | 실제 차량 오디오/절전·발열은 미검증 |
| 화면 색상·밝기·야간 지도·저장/복원 | 기존 색상 검사 8개 및 Android 저장/복원 | 실제 차량 디스플레이/야간 시인성 평가 필요 |
| 알림·로컬 한국어 명령 | 기존 안전·명령·예약/취소·저장 검사 | 실제 OS 알림 도착 시각·STT 서비스는 장치별 설정에 의존 |
| 공개 데모 링크 | 웹 빌드와 동작 검사 가능 | GitHub Pages 미활성화로 공개 배포는 아직 불가. APK는 저장소에서 다운로드 가능 |

## 속도 재확인

CPU 4배 감속·합성 10만 지점 경로·120회 GPS 갱신에서 지도 검사 8개가 통과했습니다. 초기 파싱/표시 약 **0.70초**, GPS 처리·화면 갱신 **p95 10.8ms**, 최대 **15.1ms**였습니다. GPS 상태/도움말을 추가해도 고정 위치에서 불필요하게 중심을 옮기거나 종료 버튼을 재생성하지 않았습니다. [현재 측정](../test-fixtures/validation/map-performance-v090.json). 이전 0.8.0의 약 0.57초는 그 실행의 관측값이며 모든 실행에서 동일한 수치를 보장하지 않습니다. 타일/경로 서버 지연과 실기기 FPS는 이 CPU 시험에 포함하지 않습니다.

## 재현

```bash
source scripts/env.sh
./scripts/package-submission.sh
./scripts/build-web.sh
# 다른 터미널: python3 scripts/serve-web.py --directory build/site
node scripts/web/verify-gps.cjs
node scripts/web/verify-navigation.cjs
node scripts/web/verify-navigation-detail.cjs
node scripts/web/verify-map-performance.cjs
# 아래는 실제 외부 서버 요청이며 CI fixture 검사와 별도
python3 scripts/check-navigation-live.py --output docs/validation/gps-review-live-providers.json
node scripts/web/verify-navigation-live.cjs
```

실제 Android 장치에서는 서명 APK 설치 후 정차 상태에서 정확한 위치 권한 허용 → 위치 서비스 껐다 켜기 → 실외 첫 수신 → 정차 15초 이상 유지 → 경로 미리보기 → 화면 이탈/복귀 → 권한 해제/복구를 추가 검증해야 합니다. 현재 환경의 `/dev/kvm` 부재와 과거 에뮬레이터 SystemUI 실패를 실제 장치 성공으로 대신하지 않았습니다. 기존 0.5.0 MP4는 이번 0.9.0 GPS 변경의 새 녹화가 아닙니다.

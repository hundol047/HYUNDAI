# 조작·오류·속도 재점검 · 0.8.0

0.7.0 이후 검색 도중 입력 변경, 오래된 GPS, 화면 이탈/복귀, 지연 응답과 큰 경로를 재현했습니다. 다음 문제를 실제 코드에서 수정했습니다.

| 발견한 부족한 부분 | 수정 | 검증 |
|---|---|---|
| 느린 요청을 기다리는 동안 취소 수단이 없음 | 정차 상태의 요청 취소 버튼. Android 입력 변경도 기존 요청 취소, 웹은 검색어/주변 범위 변경 시 취소 | 실제 Chromium에서 취소 후 버튼 재사용까지 이번 측정 약 44ms. 제공자/GPS는 fixture이며 네트워크 응답 시간 수치가 아님 |
| 검색어가 바뀌거나 취소한 뒤 이전 응답이 새 화면을 덮을 수 있음 | 요청 세대와 취소를 확인한 응답만 표시. Android의 취소에 즉시 반응하지 않는 모의 서비스도 이전 결과를 게시하지 못함 | 웹 지연 응답/입력/범위 변경, Android NonCancellable 지연 응답 회귀 검사 |
| 1초마다 오는 GPS 문구가 경로 오류를 덮음 | GPS 전용 상태 영역을 분리하고 검색·경로 오류를 유지 | 경로 실패 직후 새 GPS를 보내도 오류 문구 유지 |
| 좋은 GPS 뒤에 부정확한 위치가 오면 잠시 이전 위치로 안내를 시작할 수 있음 | 최신 위치가 부정확하면 시작용 위치를 무효화. 이전 시각의 위치로 복구하지 않음 | 200m 정확도 → 과거의 좋은 위치 → 새 좋은 위치 순서에서 시작 잠금/복구 확인 |
| 중복된 정지 위치가 안전 잠금 해제에 사용될 수 있음 | 같은 시각/역순 위치를 안전 판단 전에 무시 | 중복 정지 GPS로 주행 잠금이 해제되지 않음 |
| 화면 복귀 때 P 상태 재확인 전 GPS 재연결 요청이 사라짐 | 복귀 의도를 유지하고 안전 상태 확인 후 새 구독 시작. 이전 수신기의 지연 콜백은 무시 | 웹의 실제 visibility 이벤트 흐름과 Android의 등록된 LocationListener 수명 검사 |
| GPS가 옮겨졌을 때 경로를 다시 선택해야 함 | **현재 위치로 경로 다시 계산**, GPS 없는 장소 핀의 **선택 지우기** | 새 경로 요청의 출발 좌표, 기존 검색 목록 유지 확인 |
| 브라우저 시간 초과가 일반 취소처럼 처리되어 오류가 안 보임 | 시간 초과와 사용자 취소를 구분해 안내하고 조작 복구 | 실제 AbortController/모의 시간 진행으로 25초 제한 검사 |
| 10만 지점 경로에서 모든 점의 인덱스·중간 Pair와 JSON 복사 생성 | 회전 지점만 인덱싱, 반복 회전점 이진 탐색, 누적 거리 사전 용량, 화면용 좌표 직접 전달 | 회전점 재방문/근접점·기존 국제 도로 fixture 유지. 화면에 전달한 배열을 바꿔도 엔진 경로는 불변 |

## 성능 관찰

같은 headless Chromium·합성 100,000개 지점 경로·CPU 4배 감속 조건의 작은 표본입니다. 제공자 요청/실기기 화면 FPS가 아닙니다.

| 항목 | 관측 |
|---|---:|
| 수정 전 초기 경로 파싱·표시, 2회 | 1,435.4ms / 1,008.8ms |
| 수정 후 초기 경로 파싱·표시 | 569.7ms |
| 수정 후 120개 GPS 처리·화면 갱신 p95 | 8.3ms |
| 수정 후 갱신 최대값 | 11.4ms |
| 정지 위치 25회 갱신의 불필요한 중심 이동 | 0회 |
| 종료 버튼 객체 유지 | 통과 |

수정 전 첫 표시 측정값은 유효하지만, 이어진 지도 확대가 오래 걸려 시뮬레이션 차량 신호가 만료됐습니다. 안전 엔진이 시작을 거부한 것이므로 **그때의 GPS 갱신 수치는 비교에서 제외**했습니다. 검사 도구는 정상 P 재확인을 기다린 후 새 GPS로 시작하게 수정했습니다. 앱의 신호 만료·P 확인 제한을 완화하지 않았습니다. 반복 횟수가 작아 모든 기기·상황에서 같은 개선율을 보장하지 않습니다.

## Android 화면과 검사 범위

[요청 대기 화면](screenshots/navigation-pending.png)은 1280×800 Robolectric Compose 네이티브 렌더링입니다. 취소 버튼과 별도 GPS 상태가 실제 UI에 표시되는지 검사했습니다. 지도 타일은 오프라인이며 장치/실차 캡처가 아닙니다. [모바일 브라우저 대기 화면](screenshots/navigation-pending-mobile.png)은 실제 Chromium의 합성 응답 검사 화면입니다.

기존 지도·내비·색상·가게 기능을 포함해 **85개 공유 코어 + 37개 Android**, **79개 브라우저** 검사를 수행합니다. 선택적 검색 서버의 기존 **9개** 검사와 실제 가게/국제 경로 표본은 별도로 유지합니다. 현재 변경의 수명·지연·성능 검사는 합성 제공자/위치와 실제 브라우저 및 Android 프레임워크 콜백을 사용했습니다. 새로운 상용 API 실연동·실기기 GPS·실도로·Pleos FPS 검증을 뜻하지 않습니다.

공개 지도 서버의 요청 간격 제한은 유지합니다. 공개 서버의 네트워크 지연을 숨기거나 카카오맵과 동일한 교통·차선 안내를 보장하지 않습니다. 카카오 키/HTTPS 검색 서버와 GitHub Pages 공개 배포의 남은 설정은 [가게 검색 범위](PLACE_SEARCH_KO.md), [웹 배포 상태](WEB_DEMO.md)를 참고하세요. 기존 0.5.0 영상은 이번 0.8.0 변경을 새로 촬영한 영상이 아닙니다.

```bash
source scripts/env.sh
./scripts/package-submission.sh
./scripts/build-web.sh
# 다른 터미널: python3 scripts/serve-web.py --directory build/site
node scripts/web/verify-navigation-detail.cjs
node scripts/web/verify-map-performance.cjs
```

원격 Python 검사 단계가 실패한 뒤, 시작 직후 단조 시계가 60초 미만인 환경에서 캐시 테스트의 `(0, [])`를 만료 상태로 잘못 가정하는 문제를 재현했습니다. 테스트는 명시적 시계 10초를 사용해 61초 전 항목은 삭제하고 1초 전 항목은 유지하는지 확인하도록 고쳤습니다. 서버의 실제 60초 만료 정책은 바꾸지 않았습니다. 최초 원격 실행은 실패 이력으로 남기며 후속 실행 결과와 구분합니다.

[빌드 전환 시각](validation/world-soak-v0104/site-switches.json)과 각 결과의 `engineSha256`으로 구분하며, 최종 릴리스 하나가 5시간 내내 실행됐다고 해석하지 않습니다. 완료한 50개 경로의 기록은 [최종 엔진으로 다시 재생](validation/replay-soak-v0104.json)하여 모두 통과했습니다. 이 재생은 외부 서버·지도 렌더링 재검사가 아니며 5시간에 더하지 않았습니다.

## 검사 방법

- 38개국 56개 후보 경로를 준비했습니다. 실제 완료·미완료·미시도 범위는 위 표에 구분했습니다. 전 세계 모든 도로·가게를 검사했다는 뜻이 아닙니다.
- 실제 Chromium에서 앱을 조작합니다. 검색은 Nominatim, 자동차 경로는 OSRM, 화면에 보이는 지도는 OSM 서버 응답을 사용합니다. 타일 미리 수집·전 세계 가게 목록 수집을 하지 않습니다.
- 위치는 **합성 GPS**입니다. 매초 위치를 갱신하며 일반 구간은 10m/s, 마지막 접근은 5m/s입니다. 첫 리스본 경로는 15m/s였습니다. 화면·지도를 계속 갱신하고 주요 지점에서는 잠시 멈춰 타일 표시를 확인합니다. 실차·물리 GPS 검사가 아닙니다.
- 가게 검색과 좌표 목적지 주행은 독립된 검사입니다. 검색 결과가 있다는 이유만으로 원하는 지점이 맞다고 판정하지 않습니다. 빈 결과, 다른 국가, 50km 이상 떨어진 결과는 별도로 기록합니다. 마지막 항목은 검토 대상이며 그 자체가 잘못된 결과라는 뜻은 아닙니다.
- 각 경로는 새 브라우저 세션에서 순차 실행합니다. 전체 5시간 동안 지역별 기능을 검사하며, 한 세션을 5시간 유지한 메모리 내구성·실기기 FPS 검사로 해석하지 않습니다.
- 주행 위치 표본과 지도 체크포인트, 실제 검사 시간, 코드 해시, 실패 화면을 저장합니다. 마감 시 진행 중인 경로는 `deadline-incomplete`로 남기며 통과로 세지 않습니다.
- 준비·검색·지도 확인을 포함한 전체 검사 시간과 주행 세션 시간을 구분합니다. 주행 세션 시간에도 구간별 지도 확인을 위한 정지가 포함됩니다. 이전의 가속 재생 횟수를 5시간으로 환산하지 않습니다.

## 발견하여 수정한 문제

1. **동명 장소 혼동:** 강원의 `대관령 옛길` 검색이 서울 송파구의 같은 이름 식당을 반환했습니다. 실제 주소·업종에 더해 현재 위치와의 직선 거리와 먼 결과 표시를 추가했습니다. 전 세계 검색 결과를 임의로 숨기거나 다른 장소로 바꾸지 않습니다.
2. **긴 검색어 잘림:** 띄어쓰기 보정으로 검색어가 180자를 넘으면 지점명 끝 글자가 잘릴 수 있어, 원문 전체를 유지할 수 있을 때만 재검색합니다.
3. **이동 중 지도 오류 표시 지연:** 화면 이동 때마다 실패 타이머가 초기화되던 웹·Android 코드를 수정했습니다. 불완전한 지도 상태가 지속되면 이동 중에도 오류를 표시하고, 정상 로딩·명시적 재시도·재연결 시에만 대기를 새로 시작합니다.
4. **GPS 흔들림을 역방향 이동으로 오인:** 진행 위치 비교에 GPS 오차 범위를 반영합니다. 좁게 겹치는 경로는 진행 연속성과 이동 방향을 함께 고려합니다. 방향 정보가 없으면 보고된 속도 또는 최근 관측 진행량을 경로 후보 선택에만 사용합니다. 신뢰 범위 안의 후보보다 먼 도로를 선택하지 않도록 보완했습니다.
5. **부정확한 위치로 도착 확정:** 목적지까지의 거리와 GPS 정확도를 함께 확인합니다. 부정확한 GPS, 신호 끊김, 백그라운드 전환 후에는 연속 도착 근거를 다시 모읍니다.
6. **경로 복귀 인식 실패:** 경로 이탈 중 멈춰 둔 진행 위치를 기준으로 탐색 범위가 고정되던 문제를 수정했습니다. 마지막으로 경로에서 확인한 시각부터 가능한 이동 범위를 계산해 앞쪽 도로로 복귀했을 때 다시 인식합니다.

7. **주변 추천 이름 누락:** 이름 없는 객체가 공급자의 60개 응답 제한을 먼저 차지하지 않도록 이름 조건을 서버 쿼리에 적용했습니다. 한국어·기본 이름·영문 이름이 없을 때 프랑스어·일본어 등 등록된 언어별 이름도 사용합니다. 발음·어원 메타데이터는 장소 이름에서 제외합니다. 실제 브라우저에서 현지어 이름만 있는 두 장소의 누락을 재현한 뒤 수정했습니다. 또한 빈 결과를 모든 장소의 부재로 표현하지 않습니다.

8. **회전교차로 회전 방향 단정:** 실제 공급자 응답이 좌측 통행 국가에서도 `driving_side=right`를 보냈습니다. 고정 시계 방향 화살표를 제거하고 중립 원형 표지와 공급자의 출구 번호를 표시합니다. 공급자 통행 방향 필드만으로 실제 진행 방향을 단정하지 않습니다.

9. **모호한 GPS에서 확정적 회전 안내:** 정확도 범위 안에 서로 반대 방향의 도로 후보가 있으면 회전 화살표·거리·음성 안내와 도착 예상을 보류합니다. 지도와 대략적인 남은 거리는 유지하며, 정확한 위치·진행 방향이 들어오면 안내를 재개합니다. 진행 거리 오차를 숨기지 않고, 안내가 보류된 표본과 확정 안내 표본을 따로 기록합니다.

10. **외국어 도착 안내의 목적지 불일치:** 퀸스타운에서 자동차 경로 끝과 입력 목적지가 약 51m 떨어졌는데 외국어 문구가 일반 목적지 도착으로 읽혔습니다. 지원하는 31개 안내 언어 모두 차량 경로 끝과 목적지까지 남은 거리를 구분합니다. 이는 건물의 실제 출입구·주차장 접근을 검증했다는 의미가 아닙니다.

11. **날짜변경선에서 목적지·주변 가게 핀 누락:** 경로선은 경도를 보정했지만 핀은 반대편 세계 지도에 남는 웹 표시 오류를 재현했습니다. 경도 ±180°를 넘는 경로·목적지·GPS·주변 핀을 같은 지도 복사본에 맞추고, 지도 이동·가게 선택 시에도 가까운 방향으로 연결합니다. 동·서 방향의 연속 합성 GPS 주행에서도 핀·추적·도착을 확인했습니다. [브라우저 8개 검사](validation/date-line-results.json)와 Android 화면 좌표·실제 선 그리기 검사로 검증했습니다.

12. **웹 배포 ZIP의 읽기 권한 누락:** 빌드 환경의 제한적인 umask가 ZIP에 그대로 들어가 공개 파일 36개가 모두 `600` 권한이었습니다. 다른 서비스 계정으로 웹 서버를 실행하면 읽지 못할 수 있어, 배포 파일은 `644`로 저장하도록 수정했습니다. 실제 압축 해제 후 모든 파일의 권한과 APK·스크립트·영상 바이트 일치를 확인했습니다. [ZIP 검증](validation/web-release-v0104.json).

수정본은 단위·Android 화면·브라우저 회귀 검사와 기존 실제 경로의 GPS 오차/신호 끊김 재생으로 검증한 뒤 장시간 검사에 반영합니다. 수정 전후의 파일 해시와 결과를 구분해 보관합니다.

## GPS 오차·신호 끊김 회귀 검사

최종 엔진으로 [246개 조건](validation/gps-stress-v0104/summary.json)을 모두 통과했습니다. 기록된 26개 실제 경로에 반경 5·25·50m의 합성 오차, 방향 정보 누락, 속도·방향 모두 누락, 정지 중 60개 위치 입력, 12초 신호 끊김을 적용했습니다. 별도 4개 경로에서는 오차 위상과 진행 방향 흔들림도 바꿨습니다. 합격 기준은 허위 이탈·추적 끊김·조기 도착 없음, 신호 중단/복구, 정확한 최종 위치에서 도착, 확정 안내 표본의 진행 거리 오차 `max(75m, GPS 정확도 × 3)` 이내입니다.

오차 50m 조건에서 전체 표본의 최대 진행 거리 오차는 **138.1m**, 안내를 보류하지 않은 표본의 최대 오차는 **90.6m**였습니다. 이 값도 공개하며 정밀·차선 수준 안내로 표현하지 않습니다. 모호한 도로 후보는 회전 안내를 보류하고, 실제 기기의 더 정확한 위치·진행 방향 수신이 필요합니다. [기존 26개 경로](validation/replay-world26-v0104.json)와 [실제 가게 목적지 7개 경로](validation/replay-business7-v0104.json)도 최종 엔진에서 재생했습니다. 이전에 요청한 [서울시청→연세대 미래캠퍼스 113.2km](validation/replay-seoul-yonsei-v0104.json)의 위치 입력 6,930개도 다시 재생해 통과했습니다. 이 재생들은 외부 서버를 새로 호출하지 않았으며 5시간 본검사 시간에 합산하지 않습니다.

## 별도 실제 가게 선택 검사

[7개국·6개 대륙의 가게 선택 주행](validation/world-business-v0104/summary.json)에서 실제 검색 결과를 선택해 경로·도로 표시·도착·정차 후 확대/축소를 확인했습니다. 리스본 A Brasileira, 도쿄 Starbucks, 런던 Fortnum & Mason, 케이프타운 Truth Coffee, 뉴욕 Katz’s Delicatessen, 오클랜드 SkyCity, 산티아고 Cafe Haiti입니다. 이 실행은 5시간 본검사의 시간·경로 수에 더하지 않습니다. 각 실행 당시 엔진 해시를 기록하고 최종 엔진으로 경로를 다시 재생합니다.

피지 타베우니의 Waiyevo→Wairiki는 두 지점 모두 가까운 자동차 도로 좌표가 반환됐지만, 실제 OSRM 경로 요청은 HTTP 400 `NoRoute`였습니다. 앱이 임의의 경로를 만들지 않고 안내 시작을 제공하지 않는 것을 [실제 실행 결과](validation/fiji-date-line-v0104/ui-results.json)와 [화면](validation/fiji-date-line-v0104/live-no-route.png)으로 확인했습니다. 이 구간은 주행 성공으로 세지 않습니다. 날짜변경선 표시 수정은 별도의 합성 경로로 검증한 결과입니다.

## 재현 및 중단 후 이어서 실행

```bash
source scripts/env.sh
./scripts/build-web.sh
python3 scripts/world-drive-soak.py --hours 5 --output artifacts/world-soak-20261023
```

동일 출력 경로로 실행하면 저장된 진행 시간을 이어갑니다. 이미 종료된 검사는 다시 실행하지 않습니다. 새 검사는 다른 출력 경로를 지정하세요. `artifacts/world-soak-20261023/status.json`과 경로별 `process.log`, `results.json`, `samples.jsonl`에서 진행 상황을 볼 수 있습니다. 출력 디렉터리의 `site`는 검사 대상 정적 파일 사본이며 일반 개발 빌드와 분리합니다.

```bash
# 기록된 26개 실제 경로에 합성 GPS 오차·신호 끊김 적용, 외부 요청 없음
node scripts/web/verify-world-gps-stress.cjs
# 기존 표본의 진행·도착 회귀 비교, 외부 요청 없음
CABIN_WORLD_BASELINE=docs/validation/world-drive-v0103/baseline.json \
  node scripts/web/verify-world-route-replay.cjs
```

## 남는 범위 제한

최종 앱에서 리스본의 주변 추천을 실제로 요청했지만 Overpass 응답이 18초 안에 오지 않아 중단했습니다. [요청·결과](validation/nearby-live-v0104/results.json)와 [오류 화면](validation/nearby-live-v0104/screen.png)을 남겼습니다. 검색어 기반 Nominatim 길찾기 검색과 Overpass 주변 추천은 별도 기능이며, 전자의 성공으로 후자의 정상 작동을 주장하지 않습니다. 필요한 도메인은 환경 설정 초안에 저장돼 있지만 현재 런타임 정책 상태는 `unknown`이라 시간 초과의 원인을 방화벽이나 공급자 한쪽으로 단정하지 않습니다.

지도 타일이 표시된 사실은 모든 도로·상호가 최신이고 완전하다는 증거가 아닙니다. 검색 결과 없음도 미등록·폐업의 증거가 아닙니다. 공급자 원본 데이터와 별도 정답 목록을 대조하지 않은 항목은 누락 없음으로 판정하지 않습니다. 실시간 교통, 차선, 현장 통제, 차량별 통행 제한, 실제 기기 센서 정확도는 이번 합성 GPS 검사로 검증할 수 없습니다.

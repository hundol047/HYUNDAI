# 선택적 가게 검색 서버

Python 3 표준 라이브러리만 사용합니다. APK에 상용 공급자 키를 넣지 않고 기존 검색 UI에 Nominatim 호환 JSON을 반환합니다. 기본 앱 실행에는 이 서버가 필요하지 않습니다.

## 설정과 실행

운영자의 비밀 저장소/실행 환경에서 다음 값을 주입하세요. 키 값을 채팅·소스·명령 기록에 붙여 넣지 마세요.

| 환경변수 | 용도 |
|---|---|
| `CABIN_GATEWAY_TOKEN` | 필수. 운영자가 발급한 12–256자 공백 없는 ASCII 접근키. 앱에 입력할 서버 접근키이며 카카오 REST 키와 다름 |
| `CABIN_KAKAO_REST_KEY` | 선택. 카카오 Local REST API 키. 없으면 모든 검색이 Nominatim 사용 |
| `CABIN_ALLOWED_ORIGINS` | 웹의 정확한 origin을 쉼표로 구분. 기본 localhost 두 개. `*` 금지 |
| `CABIN_GATEWAY_HOST` | 기본 `127.0.0.1` |
| `CABIN_GATEWAY_PORT` | 기본 `8008` |

```bash
python3 -m unittest discover -s server -v
# 위 변수를 비밀 저장소에서 주입한 프로세스에서 실행
python3 server/places_gateway.py
```

실제 Android/웹 연결에는 운영자의 **유효한 인증서가 있는 HTTPS 역방향 프록시**가 필요합니다. 서버 URL의 `/search`와 `/healthz`를 중계하고 Android의 평문 통신 제한을 해제하지 마세요. 웹을 사용하면 정확한 공개 origin을 등록하고 역방향 프록시의 검색어/좌표/Authorization 로깅도 끄세요. 앱 내 정차 상태의 내비게이션→서비스 설정에서 검색 **기본 주소**와 서버 접근키를 입력합니다. `/search`는 앱이 붙입니다. 접근키는 메모리에만 보관하므로 앱 프로세스/탭 종료·개인정보 초기화 후 다시 입력합니다. OSRM 경로 요청에는 이 키를 보내지 않습니다.

명시적 `bounded=1`과 유효한 반경 20km/GPS/viewbox가 있는 한국 주변 검색에만 Kakao Local을 호출합니다. 국가 제한 없는 검색은 카카오 키가 있어도 Nominatim을 사용합니다. 한국 근방의 사각 영역에는 인접국 일부가 포함되므로 카카오 결과가 비어 있으면 같은 검색어/영역으로 Nominatim을 조회합니다. 공급자 호스트는 코드에 고정되어 임의 프록시가 되지 않습니다. 6개씩 최대 18개라는 클라이언트 제한 안에서 카카오 15개 페이지의 경계를 이어 읽습니다. 카카오가 반환하지 않는 전화/영업시간 등을 임의로 만들지 않습니다.

검색 요청은 Bearer 인증, 정확한 CORS origin, 최대 2개 진행 요청, 공급자 요청 간격 1.5초, 최대 2MB 응답 제한을 사용합니다. 위치/검색 캐시는 메모리 최대 128개·60초이며 서버의 유휴 주기에도 만료 삭제합니다. 핸들러는 검색어·위치·헤더를 로깅하지 않고 공급자 오류 원문을 노출하지 않습니다. 공유 공개 서비스로 운영할 때는 별도 사용자 인증·사용자별 허용량·모니터링이 추가로 필요합니다.

## 검증 상태

- 실제 Nominatim 중계·인증: [로컬 통합 결과](../test-fixtures/validation/place-gateway-live.json).
- 카카오 어댑터: 모의 응답 계약 검사. **API 키가 없어 실서버 미검증**, 계정 생성·유료 서비스 활성화를 하지 않았습니다. 운영자는 최신 공식 문서/약관/앱 등록/사용량 제한을 확인해야 합니다.
- Google Places: 구현하지 않음. 앱의 Google Maps 버튼은 외부 검색 링크입니다.
- HTTPS 서버 배포·가용 시간·모든 가게 포함을 보장하지 않습니다. `healthz`는 프로세스/설정 유무만 표시하고 공급자 연결 검증을 뜻하지 않습니다.
